6. IOC ENRICHMENT

The extracted IP and domains were identified as reserved documentation
values within the synthetic training sample.

The IP 198.51.100.23 is a TEST-NET documentation address.

The domains use the .example namespace, which is reserved for
documentation and examples.

Because the indicators are intentionally non-production values, no
real-world malicious reputation was assigned to them.


7. PHISHING INDICATORS

The investigation identified the following characteristics:

- Sender domain differs from the apparent corporate domain.
- Reply-To address uses a different domain.
- SPF authentication resulted in softfail.
- DKIM authentication was not present.
- DMARC authentication failed.
- The message creates urgency around password expiration.
- The message threatens account or mailbox suspension.
- The visible URL differs from the actual hyperlink destination.
- The message uses an account verification/password-reset theme.


8. MITRE ATT&CK MAPPING

T1566.002 — Phishing: Spearphishing Link

Evidence:
The email directs the recipient to an account verification/password-reset
link.

T1036 — Masquerading

Evidence:
The sender presents itself as "IT Helpdesk (corp.example)" while using a
different sender domain.

The following techniques were intentionally not mapped because the sample
does not provide sufficient evidence:

T1078 — Valid Accounts
T1056.002 — Input Capture: GUI Input Capture


9. ANALYST ASSESSMENT

The email demonstrates multiple characteristics consistent with a phishing
attempt, including sender impersonation, authentication failures, urgency,
Reply-To mismatch, and hyperlink destination mismatch.

Within the controlled training scenario, the email is assessed as HIGH risk.

The available evidence supports identifying the message as suspicious;
however, the synthetic nature of the sample prevents conclusions about
real-world infrastructure or threat-actor activity.


10. RECOMMENDED SOC RESPONSE

If this were observed in a real organization:

1. Quarantine the email.
2. Identify other recipients of the same message.
3. Search email telemetry for the sender, Reply-To address, subject, and
   URL.
4. Block confirmed malicious indicators after validation.
5. Check whether any users interacted with the link.
6. If credentials were submitted, initiate the organization's credential
   compromise response process.
7. Document the incident and preserve the original email for further
   investigation.
